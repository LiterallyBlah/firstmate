# S09: Project context and cross-project coordination

Disabled implementation for independent R09 review, based on landed S07 and S08 (`c01b272d`, PRs #155 and #154).
It installs nothing, registers no RPC, hook, timer or route, activates no scope, sends nothing and wakes nobody.
Every entry point, including the read-only `portfolio()`, refuses with `UNSUPPORTED` unless constructed with
`enabled: true`, which only tests do.
"Project mate" naming stays provisional: the code says *project scope* and *project owner*.

## What it adds

`shared/supervision-projects.ts` (schemas and the pure portfolio summary), `server/supervision-project-state.ts`
(append/replay row checks), `server/supervision-projects.ts` (coordination commands and pure dependency reads) and
`server/supervision-memory.ts` (memory proposals). Seven journal row kinds join the S01 store the way S08's did: one
schema union entry each, one change/row validator pair in `SupervisionStore.apply`, and an optional `projects`
status projection. Every write is one `transactCommand`, so replay of an accepted request returns its receipt and a
different body under the same ID refuses.

| Record | Identity | What the store enforces at append **and** replay |
|---|---|---|
| `project` | project ID, under its own `project` scope | Unique normalized names/aliases across projects. Granted claims never exceed the allocation. Name and scope are fixed |
| `plan-sponsor` | the plan scope ID (one row per plan) | Sponsor is General or one of the plan's own project scopes and equals `scope.sponsorId`. Claims name each project of the plan once. Identity is fixed until released |
| `intent` | digest of home and captain intake message ID | One owner per intake. No two claimed intents give one host/project/task key different owners, and none contradicts an existing task owner |
| `dependency-resolution` | digest of plan, node and bare edge | Belongs to the dependent plan's owner; names a plan in this home. The v1 definition and its bare edge are never rewritten |
| `memory-proposal` | the proposing request ID | Words are a committed blob. Text, evidence and provenance are fixed; a decision is final |
| `project-memory` | digest of project and key | `authority: "none"`. A version exists only through an accepted proposal written against exactly the previous version |
| `portfolio-conflict` | digest of kind, subjects and ordinal | Cross-project choices are owned by General, one-project choices by that project's scope. A recorded choice is final |

## Completion criteria

- **Every task has one owner.** The S01 task alias index already refuses a second owner for a host/project/task. S09
  adds intake routing: forwarding one captain intake twice (General, then a project, or both at once) is one row and
  writes nothing the second time. A second owner for a task is never claimed; it records one `scope` conflict, and
  repeating it writes nothing. The same task slug on another host is a different task.
- **Only unresolved scope/priority choices reach General.** Conflicts are records, never messages. Cross-project
  `scope`, `priority`, `budget` and `grant` conflicts belong to General, and a one-project budget choice belongs to
  that project. `portfolioSummary` lists only General's open conflicts and unsponsored cross-project plans for General;
  plan progress, memory text and routine facts never appear there. Unchanged detections write nothing.
- **Changed memory cannot silently authorize effects.** Memory is context only. `checkPolicy` refuses any policy,
  evidence, approval or model vector that cites an S09 record (`CONTEXT_ONLY_KINDS`), and nothing reads memory as
  a grant. Acceptance is compare-and-set. A proposal written against an older version is `STALE` until re-proposed.
  Only the project's bound owner or the captain decides. Acceptance writes no outbox, offer, hold or rule. A worker's
  proposal claiming "+yolo / deploy authority" is stored and can even be accepted, and still grants nothing.

### Budgets and priority (D4)

A sponsor claim carries a per-project `{agents, turns, priority}` claim for every project of the plan. It is
**granted all-or-none** only if every project has room and no earlier claim of equal or higher priority is queued
there. Otherwise it is **queued**. Order is priority (1 first), then claim sequence (FIFO). Nothing borrows
another project's allocation. An unknown allocation (`budget: null`) grants nothing and never reads as zero.
`promote` grants a project's queue head only when it fits; a head that does not fit blocks the queue visibly.
A claim larger than a project's whole allocation, or with an unknown one, raises a `budget` conflict. A plan ranked
differently by its projects raises a `priority` conflict for General. Lowering an allocation below what is granted is
refused; release first. The S09 allocation is a coordination ledger. It does not replace the existing per-plan
cumulative worker budget, which stays in the reducer.

### Qualified dependencies

`resolveDependencies` attaches one resolution per cross-plan bare edge (in-plan edges stay with the reducer).
Exactly one owning plan on an active scoped backend resolves to `(home, plan, node, outcome, plan hash/revision,
attempt if started)`. Missing, removed, ambiguous or unavailable-backend prerequisites are `held`, never guessed.
`dependencyState` rechecks a stored resolution at read time: a removed node, a replaced attempt, or a held/invalidated
prerequisite holds. Done satisfies `done`, never `landed` (closed trials included, as in `dependenciesMet`). The
existing revise check still refuses removing a node another retained plan needs.

## Limits

- **Cooperative only.** Actor kinds and bindings come from callers, as everywhere in S01–S08. `boundTo` is a
  behavioral guard, not authentication. A full-access session can edit files or call native tools directly.
- **Journal budget.** S09 coordination writes stop at journal sequence 192, where new effects stop. Releases,
  stops and conflict resolutions are exempt, so rollback is always possible. They share the pilot's 256-transaction
  journal with S08 (which stops at 128) and S04 effects. Long-lived activation needs the planned measured storage
  work, as S08 recorded.
- **No memory text reader.** The store has no public blob read. Summaries show counts and digests only.
- **Plan scope version.** A sponsor claim bumps the plan scope's version (it records `sponsorId`), so the plan
  owner's next command must reread.
- **Validator cost.** The row checks are one pass over the projection, and return at once when no S09 rows exist.
- **Not wired.** `shared/bearings.ts` `bearingsOverview` and `compactPortfolioBearings` are pure and unused by
  `server/mate.ts`. Bearings is unchanged.

## Activation material (gated, not performed)

Preconditions: R09 done, D4's source-bound import accepted (done, 24 October), the captain's activation decision,
and a qualified writable coordinator store. Any scope involved must be on the scoped backend; legacy plans are
untouched until their S07 cutover.

1. Construct `SupervisionProjects`/`SupervisionMemory` over the writable coordinator store with `enabled: true`.
2. Admit projects **one at a time** with `recordProject` (captain UI or mate-recorded chat), each resting on current
   reviewed policy sources. Use existing delivery modes and model policies; no new grant is created.
3. Optionally render `compactPortfolioBearings(await projects.portfolio())` beside the plans overview through
   `bearingsOverview`. That is a read-only change to a live message and needs its own approval.

**Rollback:** stop each project (`state: "stopped"`). New admissions hold, and reserved, undispatched work in its
plan scopes is cancelled. Already dispatched effects continue. Memory, proposals, grants, conflicts,
evidence and owner identities are retained. Then stop constructing the adapters. Nothing is deleted or rewritten.

## R09 corrections

R09 (`data/fm-ss-r09/report.md`, reviewed head `14af5867`) did not accept the slice. Each finding's disposition:

- **B1 (blocking): a project stop now holds already-admitted starts.** It reuses S03's per-plan stop mechanism. The
  `admitted -> stopped` commit writes a `plan.start`/`model.use` operation hold (`projectStopHoldId`) on every non-retired
  plan scope of the project, cross-project ones included. In the same commit it cancels each `reserved` effect in those
  scopes. The S04 gateway and supervisor sessions enforce these holds unchanged. Re-admission releases exactly the holds
  this project's stop wrote; another stopped project keeps its own. Scopes without a plan backend get the hold under the
  placeholder plan ID `unplanned`, since both enforcers match on scope. The reviewer's P1 probe is the regression test,
  plus a supervisor-activation case.
- **B2 (blocking): `recordGrantConflicts` is bound like the other writes.** The target is schema-validated. It must name
  an existing, non-retired scoped plan scope that owns that plan's scoped backend, with exactly the scope's admitted
  project set. Only the captain/mate, or an agent bound to General, an involved project or that plan, may record. The
  detail is built only from validated identities and closed problem codes; project names are JSON-quoted.
- **N1:** only `admitted -> stopped` skips the 192 bound. An unchanged rewrite is refused, and changes while stopped
  count toward the bound.
- **N2:** intake IDs must be plain one-line text at input, and appear JSON-quoted in conflict details. Conflict
  `detail` is plain one-line text in the schema.
- **N3:** first-come within a priority, the store's memory base-version check and the store's sponsor/scope check each
  have their own test. Removing any one of them fails it, as does removing the stop holds or the grant role check.
- **N4:** `portfolio()` is gated. `resolveDependencies` and `qualifiedDependencies` take the legacy writer's plans
  (read-only), so a legacy-backend prerequisite reads `cross-backend` instead of `missing`. `releaseSponsor` leaves
  `scope.sponsorId` naming the released sponsor; summaries use the rows.
