# S02: local ingress and per-scope mailboxes

S02 adds an explicit, observe-only library over S01's transaction journal and a read-only status RPC.
The plugin does **not** initialize a store, claim a coordinator, attach ingress hooks, poll a new
source, prepare offers, send messages or start a supervisor. Offers default off, with no environment,
configuration or RPC switch. Existing timers, watch configuration, role checks and legacy delivery
routes remain in place. S04/S06 qualification and separate installation/activation authority still apply.

The base is S01 merge `a75abc21552e14615d02b443efe2a068c84bac1c`. R01's narrow re-review accepted
`36d086045a72fbfd4f8b94aaed19c007a7d8ac2d`, closing both ownership findings. Existing automatic
plans, reducers, dependencies, evidence checks and cumulative budgets are reused unchanged.
No workflow executor or alternate plan model is introduced. D4's source-bound policy choice belongs
to the parallel S03 slice; this slice imports no grants.

## Durable contracts

`shared/supervision-inbox.ts` adds strict journal rows for immutable events, assignments, source
coverage, mailboxes, offers and accepted command identities. `SupervisionStore.transact` publishes
these with the existing blob, scope, attempt and task rows under the same expected-version,
coordinator, tip/event/publication boundary. There is no second event log or outbox writer.

`SupervisionEvents.admit` stores a capped evidence blob before the ingress transaction. The
transaction commits event, disposition, source baseline/gap and mailbox position together.
Interrupted publication exposes none of those rows until the exact publication is reconciled.
An orphan blob is inert. An event without its disposition, an unregistered payload handle or a
second primary for one consequence refuses before publication. Accepted request replay returns the
original receipt; changed input under that identity refuses. Replay is available when offers are disabled.

Source identity retains kind, local host, source key and epoch. Semantic identity uses the exact
worker plus typed kind and turn/outcome or permission ID; source provenance does not multiply the
consequence. Null turns use their observation identity, never one shared null-turn key. Changed
content under a reused source key is retained as conflict evidence with a visible gap. Late evidence
does not update task/attempt/workflow state or regress a source cursor.

Assignment resolves only through registered local worker → attempt → task → scoped owner. Titles,
labels, status lines, quoted tags and payload prose cannot select a recipient. Historical attempts
participate in ambiguity detection; a reused worker without an exact retained association enters
triage. An explicit `resolve` may assign a well-formed primary after unique registry evidence appears,
rechecking it at publication. Prior duplicate provenance remains retained. Malformed or oversized
subjects are quarantined separately, while healthy scopes continue.

Payloads are capped at 16 KiB; local adapters retain typed identifiers, counts and hashes rather than
transcript bodies, tool arguments, permission descriptions or provider error text. Oversized content
retains its digest/size and an omission marker. Payload references are committed content-addressed
blob handles, with no arbitrary-path reader exposed. This is not an authenticated input channel or a
secret boundary against full-access same-user peers.

## Local observation and recovery

`registerLocalSupervisionIngress` is an **unattached** future seam using the supported
`agent.turn_ended`, `agent.permission_requested` and `agent.permission_resolved` hooks. Explicit
`boot` records the non-durable hook interval. `reconcile` uses the existing supported catalog reader
and the SDK's public typed `agents.ref(id).timeline.refetch` API. There is no private history fallback.

An empty hook triggers bounded canonical refetch. Empty/missing-turn, failed, gapped, stale-cursor,
changed-epoch, unordered and oversized pages remain explicitly incomplete. A changed epoch starts
with no cursor; a later explicit valid tail establishes only **bounded** coverage. `hasOlder` is not
lossless history. A complete page with `hasNewer` can advance its persisted cursor while retaining a
visible remaining-page gap. A fetch pins the source version captured before I/O, so a slow old page
cannot overwrite a newer baseline. Fetches happen outside the journal and mailbox locks; catalog
observations for independent workers can progress concurrently.

Typed timeline metadata and ordinary catalog snapshots are `observed` with an evidenced, deterministic
no-action disposition. They do not acknowledge a model offer or prove completion. Error/attention
catalog observations remain pending; permissions retain exact IDs. Hook finishes are reported facts,
never verified workflow `done`/`landed`. Existing receipt observers retain their separate semantics.

At 10,000 unresolved primary events, new admission records a pressure gap and keeps the previous
baseline; it returns no admitted event ID. Duplicates retain provenance without spending another
pending slot. Critical history is never evicted. S01's journal/blob byte alarm also remains in force.
A filesystem/publication failure returns `HELD`; when storage cannot accept even a diagnostic, no
durable diagnostic is promised. Existing rows/cursors remain retained and no effect is dispatched.

## Offers, acknowledgements and handling

`SupervisionInbox` is an internal fixture-qualified command library, with `offers: false` by default.
There is no send callback. S04 must qualify the receiving runtime, read the actual owner idle state,
recheck it immediately before its send, count model turns and reconcile delivery uncertainty.
The `ownerIdle` input here is cooperative evidence supplied by that future caller, not a runtime fence.

An explicit offer contains at most 32 events and fits the 24 KiB evidence-envelope budget. There is
one unacknowledged offer per scope. The scope's active binding/epoch and row versions are pinned;
General's running state and conversation lock are not consulted. `beginSend` commits an uncertain
boundary before any future send; transport acceptance is a distinct state. A lost response is not
automatically resent. Explicit non-admission evidence permits informational retries under the same
offer ID, exponential backoff and a three-send cap. It grants no imperative effect authority.

Acknowledgement names the exact offer/page/current epoch. It handles nothing. A later explicit
handling record requires committed terminal effect references in the same scope, or a no-action
reason with committed evidence. Acknowledged-but-unhandled items remain pending. The contiguous
watermark advances only across terminal dispositions and cannot jump a hole. Status text is never
an acknowledgement.

After a separately checked higher-epoch replacement, `reoffer` retires the prior informational
offers and returns unhandled facts to assignment, retaining event/consequence identities, receipts
and spend. It processes at most seven old offers per transaction to stay within S01's mutation cap;
further explicit calls continue the retained inventory. It does not replace a binding itself or prove
the old full-access actor quiescent. No automated takeover, effect retry or receiver fencing is claimed.

`crew-seen` receives one read-only scope snapshot per completed General turn. It excludes registered
scoped workers from the legacy time-based attention-clear inference, including retained identities.
A held journal refuses that inference. No mailbox state is changed by clearing or retaining a sidebar flag.

## Read-only RPC for S05

`firstmate.supervision.inbox` input is `{scopeId?, pageKind?: 'events'|'sources'|'offers', after?: 0,
limit?: 32}`. It returns `firstmate.supervision-inbox/1`: journal sequence/hash/freshness, exact
assignment/attempt and evidence handles, complete pending/triage/quarantine/unhandled-ack/uncertain
offer/source-gap counts, oldest pending age, admission holds and a scope's contiguous watermark.
Held projections label counts as a lower bound. Coming up and legacy Needs-you counts are untouched.

Each collection uses a separate page, at most 32 rows and 24 KiB for the complete response.
`nextAfter`/`hasMore` page events by scope ordinal (global events by retained primary position), and
sources/offers by collection offset. Counts describe the complete selected scope, independently of
the displayed page. Source gaps remain visible through counts and source pages. Reads do not initialize,
repair, attach sources, claim ownership, open a session or call a model. They return no raw blob content.

## Verification and limits

The source/test digests, exact commands, runtime and fresh results are recorded in
[`s02-validation.json`](s02-validation.json). All execution uses test/setup.ts's temporary PASEO_HOME;
no live home, provider call, plugin install/reload, routing, watch edit, migration or delegated agent is used.

| Acceptance | S02 evidence | Deferred boundary |
| --- | --- | --- |
| A02 | Duplicate/reordered multi-scope observations retain one primary consequence and all source provenance. | Required review/head verification and a next-step effect belong to S04/S08; no reviewer outcome is accepted here. |
| A06 | Atomic cursor/event/disposition faults, explicit boot gaps, typed empty/gapped/epoch recovery, stable requests and capped informational retry. | No lossless hook claim, remote adapter or imperative retry. S02 fault hooks simulate interrupted publication; existing S01 tests separately exercise real process death. |
| A08 | Busy owner and delayed fetch do not block the other scope's admission/offer/ack. No General dependency or send API. | No ten-minute live workload, provider timing, worker/reviewer creation or model-cost claim. |
| A09 | Resource-free stored pages, complete counts, lower bounds, gaps, owner/attempt and pending age. | S05 owns themed/phone UI; no UI added here. |
| A17.preserve | Existing timer/watch source unchanged; isolated before/after legacy configuration and no-resource API canary. | No occurrence scheduler, DST/catch-up/host cleanup claim; D5/S10 remain separate. |

Additional negative tests cover untrusted recipients/payloads, unregistered result evidence, wrong
scope/epoch, false watermark, source-key conflicts, reused-worker ambiguity, source-version races,
disabled-offer replay and individual quarantines. Publication damage holds the S01 authority store;
malformed ingress payloads hold only their subjects. Source gaps remain uncertainty, not an implicit
approval to act. Performance targets, installed-runtime delivery and full pilot acceptance remain unqualified.

Rollback stops future offers/attachment, retains the journal, cursors, dispositions and spend, then
reconciles pending/uncertain receipts before any separately approved enablement. There is no deletion,
budget reset, legacy history conversion, release adapter or live activation material masquerading as approval.
