# S07: history import and single-writer cutover

Slice S07 of the scoped-supervision proposal (`fm-supervision-plan-corrections`), built on S06 at
`503e0c35`. It covers code, isolated fixtures and gated activation material only. Nothing here is
installed, routed, armed or run against a live home. The proposal's D1–D6 choices are not taken here.

## Protocol, as built

1. **Arm** (`arm`). This writes `.scoped/armed.json` and snapshots the queue entries that already exist. From then on, every gated send leaves a claim. A pre-arming entry can later be classified as `uncertain`, never as unsent. Unarmed, the gate writes nothing. A test checks that no `.scoped` directory appears.
2. **Freeze** (`prepare`). Both of these are held while the target's state is captured: the gate lock, then the legacy writer's own lock (`WorkflowPlanStore.locked`).
   - **What is captured:** every event, tip and publication file of the plan, by name and SHA-256, plus the delivery inventory.
   - **Refusals, with no freeze:** a corrupt, quarantined, retired or recovery-receipt history, a replay-parity mismatch, a send that is live in flight, and more than 200 affected deliveries.
   - **The sidecar:** `freeze.json` is published exclusively.
   - **From that point:** the legacy writer refuses the plan, and so does every gated enqueue or send whose identity resolves to it.
3. **Prepared** (one scoped transaction, request ID = migration ID). It contains:
   - the scope (`transferring`);
   - the prepared scoped backend, bound to the source hash;
   - the byte-exact `workflow-import`, whose original request receipts replay;
   - scoped task rows for the run nodes;
   - the receipt, with its imported request/attempt/budget/hold index, dependents, launch records and projection preimage;
   - one disposition per affected delivery.

   `prepared.json` follows. While the backend is `prepared`, neither backend can write. The store refuses scoped workflow mutations, and it refuses backend activation outside a committed migration.
4. **Reconcile.**
   - **Transfer facts:** the `legacy.fact` outbox mapping is committed first. Only then is the old queue entry removed, by ID and payload hash.
   - **A payload mismatch** removes nothing and turns the disposition into a hold.
   - **Already-handled entries** are removed after their disposition.
   - **Drains** are accounted once the recorded old owner's send has a receipt.
5. **Resolve a hold** (`resolveHold`). This is an explicit, evidence-bound move to `already-handled` or `drain-legacy`. It never sends. A drained watch entry gets a drain allowance, so the legacy flush may finish its delivery to General.
6. **Barrier.** Everything is verified again:
   - the freeze sidecar and the source fingerprint;
   - that no disposition is unaccounted;
   - that no claim is open;
   - that no delivery for the target has appeared outside the inventory.

   The barrier then records the prepared sidecar hash.
7. **Commit.** `committed.json` is published first. Then one transaction commits the migration, activates the backend and activates the scope. After this, the legacy writer refuses the plan through two separate checks: the sidecar, and `legacyRoute`, which looks at the scoped backend. Deleting the sidecar does not reopen it.
8. **Acknowledge.** The bound owner handles each transferred fact through the existing typed path: a scoped `ack` command result, then `SupervisionCommands.acknowledge`. `recordAcknowledgements` copies that result onto the disposition. `report().complete` stays false until every transfer has its owner's result. Commit alone is not a completed transfer.

`resume` finishes the stage a crash interrupted:
- **No scoped migration yet:** it recomputes the snapshot under the same locks and requires the same source and inventory hashes as the freeze.
- **Prepared sidecar missing:** it publishes it.
- **A committed sidecar over a barrier:** it activates.

Anything that does not match stays held.

## Dispositions

| Source | Identity kept | Route |
|---|---|---|
| Plan captain action (`firstmate-plan-<id>`) | Action ID and note ID. Handled and pending keys `<plan>:captain:<id>` and, for `changes`, `<plan>:changes:<id>`. `notified` is recorded as an observation only. | `already-handled` when every key is handled. Otherwise `transfer-fact`, with one stable consequence ID, whatever `notified`, the queue or acceptance says. |
| Burst note for the plan's worker | Note ID and whole persisted payload (parts, relates, hold). | `transfer-fact`. Merges and extensions for a frozen worker are refused, so the payload cannot change under the disposition. |
| Decision submission for the plan's task | Request, revision, submission and message ID. Payload hash, Needs-you outcome, claim receipt. | `hold`, imperative. It is never re-sent or re-answered. It moves only by explicit evidence. |
| Watch queue row mentioning the plan | Exact name, run and kind, plus the payload hash. No invented ID. | `hold`, opaque. It stays with its legacy owner. Unrelated rows keep flowing. It drains only when explicitly resolved. |

The delivery state comes from evidence, never from queue presence:
- An `accepted` claim gives `accepted`, which is not `handled`.
- An `uncertain` claim, a claim left without a result by a stopped process, or a pre-arming entry gives `uncertain`.
- Otherwise the state is `queued`.

## Limits (stated, not solved)

- **Cooperative, in-process.** The gate and the sidecar bind compatible code only.
  - An older binary does not read them, so it must be stopped before a cutover. That is a precondition, not a fence.
  - Raw file edits can bypass everything. The source fingerprint check catches edits to the plan's files at barrier and commit.
- **No automatic replay.** An uncertain imperative stays held, with its spend retained, until explicit evidence resolves it.
- **No U2.** Native subscription ownership (U2) is untouched. A worker's original parent callback remains with its original owner.
- **No bulk migration.** No archive, unknown-host adoption, RPC, timer or start-up path is added. Nothing constructs an enabled migrator.
- **One scope at a time.** One scope per cutover, up to 200 affected deliveries, and a legacy chain of up to 5,000 events. The scoped journal's pilot ceilings still apply (256 transactions).
- **Damaged sidecars fail closed.** A damaged sidecar makes the gate refuse plan-note, burst and decision deliveries everywhere until it is reconciled. Unrelated generic notes and watch output still flow.
- **Watch matching is a clue.** Watch rows are matched to a target by whole-word mention of its plan, node or worker IDs. A mention can hold a transfer. It never chooses an owner.
