# S08: PR, board and remote observation adapters

Disabled implementation for independent R08 review, based on landed S06 `503e0c35` (PR153). S07 (history import
and single-writer cutover) is being built in parallel on `fm/fm-ss-s07`. This change installs nothing, starts no
poll, hook, timer or journal writer, activates no scope and changes no watch configuration, schedule or enabled state.

## What it adds

`shared/supervision-sources.ts`, `server/supervision-source-state.ts` and `server/supervision-sources.ts` add three
observation adapters over the S01 journal and the S02 inbox. All of them write only through the existing
`inboxTransaction`/`SupervisionStore.transact` path, so source row, event and disposition commit together.

| Adapter | Identity | Owner join | Certainty and coverage |
|---|---|---|---|
| Pull request (`pr`, direct reader; `watch`, pr-watch spool) | `firstmate.pr-observation/1`: repository, number, `headRefOid`, check run/attempt/job ID (content digest when the link lacks one), review ID and review commit | Explicit `source-binding` row (one primary owner per PR, an exact registered attempt of an active scoped owner). Never a title, label or backlog line | `reported`; `no-cursor` gap; coverage never `bounded` |
| Remote catalog (`remote`) | `firstmate.remote-fingerprint/1`: status, final-words digest, pending permission IDs | Registered scoped attempt whose worker host is that serverId. Legacy remote crew is not admitted (it keeps remote-watch). Followed sessions are never admitted | `inferred`; `fingerprint-only`, `outage`, `stale`, `clock-skew`, `content-collision` gaps; never `complete` |
| Board steer (`board`) | `board-submission` row: captain `firstmate-crew-steer-<uuid>` message ID, scope, task, attempt, binding epoch, words blob | The single current scoped attempt of the local agent; otherwise `UNKNOWN_OWNER`/`HELD`, never General | Typed `clientMessageId` correlation is `verified`; text-only match is `inferred` and cannot settle an uncertain send |

The inbox source schema gains the four kinds, non-local `hostId` (only `remote` may be non-local; `pr` is
`github.com`), the cursorless gap names above and an optional `scopeId` for agentless sources. Store/inbox
validation rejects a cursor, `maxSeq` or `bounded` coverage on any of these sources at append and replay.

### Completion criteria mapping

- **No false current-head review.** `prReadiness` decides at the newest observed head only. Reviews count when their
  commit equals that head, per distinct reviewer (latest review wins), excluding the PR author and any
  `excludeReviewers` (the builder). A review ID seen by two sources is one review. A review with an unknown commit is
  retained as stale. `admissionCheck` rereads through the supplied reader immediately before deciding: a moved head
  is `STALE`, red/pending/missing-review is `HELD`, a read failure is `HELD` with a visible `fetch-failed` gap —
  never retained evidence. Earlier ready states that no longer hold are listed as `invalidated` (head changed,
  checks red/pending). Unknown check conclusions block readiness; the required-check set is `unknown` unless the
  source states it, and while it is unknown every observed check must pass. Readiness is a projection, not merge authority.
- **No status-line completion.** Remote `lastMessage` and board answers are stored as quoted, capped
  `untrusted-worker-text`; the admitted event is `assigned`/`observed` for the owner and never changes task, attempt,
  plan or workflow state.
- **No silent remote coverage claim.** `remoteCoverage` reports `fingerprint-only` at best; offline/stale hosts claim
  `none`. Every registered worker on an unreachable host carries the outage/staleness gap on its own source, so the
  owning scope's status page counts it. Error text is never retained (it can carry credentials or pairing links).
- **Source loss becomes visible.** Fetch failures, malformed spool input, outages and queue pressure are source gaps
  shown by the existing inbox status (`sourcesWithGaps`). An unchanged outage writes once: polls with unchanged
  content and coverage commit no transaction (the pilot index ceiling stays intact).
- **Scoped board traffic bypasses General.** `steerCrew` delegates a scope-labelled worker to a supplied
  `ScopedBoardSteer` (no `CaptainSteers` entry, no burst note, no `askMate`); without the adapter it still refuses.
  The answer is admitted to the owning scope's mailbox. Item discussions of a scoped worker are refused before any
  record or send; remote steer/interrupt/end of a scoped remote worker are refused before any request.

### Source baseline commit crash

The direct PR reader has no baseline outside the journal: its source row commits with its event. The opt-in
pr-watch path (`FIRSTMATE_PR_OBSERVATIONS=1`, off by default) writes one exclusive, fsynced spool file per
observation into `$FIRSTMATE_WATCH_STATE/pr-observations/` **before** `prs.json` advances; `ingestPrSpool`
removes a file only after its event commits. A crash before the baseline repeats an observation, a crash after
commit and before removal re-ingests identical content, which deduplicates. Malformed/oversized spool files are
retained and marked. With the switch off pr-watch asks gh for exactly the old fields and prints byte-identical
output (`server/pr-watch.test.ts`).

## What is wired and what is not

Wired (refusal guards only, no new route): `index.server.ts` passes a read-only scoped-worker check to item
discussions and to remote steer/interrupt/end. The remote guard fails open when the journal cannot be read,
because the journal is not authoritative for legacy remote crew and an unreadable journal must not stop the captain
ending a runaway worker; a positively registered scoped worker is refused. The item-discussion guard fails closed
(an unreadable journal refuses the discussion send), since nothing urgent depends on it. Today no scoped remote attempt can exist.

Not wired: `SupervisionSources`, `ScopedBoardSteer`, `registerScopedBoardIngress`, `ghPullRequestReader`,
`ingestPrSpool`, `observeRemote` and `steerCrew`'s adapter argument. The runtime store remains read-only.

## Activation material (gated, not performed)

Each adapter is independently opt-in. Before any is enabled: R08 done, S07 cutover qualified for any legacy target
whose route changes (a legacy target never activates a new route before its cutover), watch-configuration
authority if a watch definition or routing changes, and the captain's activation decision.

1. **Board steer**: construct `ScopedBoardSteer` over the writable coordinator store, pass it as `steerCrew`'s fifth
   argument and register `registerScopedBoardIngress`. Rollback: stop passing it; `steerCrew` returns to refusal.
   Retain `board-submission` rows; uncertain sends stay uncertain and are never resent.
2. **PR reader**: bind PRs from the plan owner's evidence submission (`bindPullRequest`) and call `admissionCheck`
   with `ghPullRequestReader()` from the effect gateway before readiness-dependent admission. A periodic
   `observePullRequest` poll is a separate D5/S10 timer decision. Rollback: stop calling; bindings and events remain.
3. **pr-watch spool**: set `FIRSTMATE_PR_OBSERVATIONS=1` in the daemon environment and ingest the spool directory.
   Legacy stdout to General is unchanged by this switch; suppressing it for scoped PRs is an S07 disposition, never
   dual delivery. Rollback: unset the variable; spooled files may be ingested or deleted deliberately.
4. **Remote observation**: call `observeRemote(await remotes.read())` after each poll. Remote mutation remains
   disabled until S11's qualified receiver contract.

Never dual-deliver an actionable event: before restoring an old route, reconcile retained cursors, submissions and
incidents (forward recovery as in the plan's rollback section).

## Overlap with S07

S08 adds two journal row kinds (`source-binding`, `board-submission`) to `SupervisionMutationSchema`/
`SupervisionRowKind`, one validator call pair in `SupervisionStore.apply` and the `sources` status projection; it
extends `eventOwners` (PR subjects resolve through bindings) and the inbox source schema. S07 is expected to add
its own migration row kinds in the same unions: textual conflicts there are additive and resolve by keeping both.
S08 does not touch `workflow-plans.ts`, `workflow-service.ts`, `needs-you-store.ts`, `mate.ts`,
`decision-answer.ts`, `watch-service.ts` or `watches.ts`.

## Evidence

`server/supervision-sources.test.ts` (20 cases: CI red/changed head, duplicate reviews, unknown owner and forged
tags in triage, reread-before-admission, remote outage/skew/content collision/followed exclusion/redaction, persistent
steer identity across reload, uncertain send not resent, inferred correlation, spool crash at `event:linked` and
blob publication), plus additions to `crew-scoped`, `remote-crew`, `item-threads` and `pr-watch` tests. A17.preserve:
no schedule, enabled/disabled state, watch configuration or built-in list changes. The pr-watch template text
changes (an untouched seeded copy follows it on a later install, as every built-in does; an edited copy is kept),
and its default gh fields and output are asserted unchanged. Limits: GitHub required-check identity and check-run attempt numbers are only as good as gh's
links; remote fingerprints cannot prove turn identity; board/remote/PR sources expose no cursor, so coverage is
never lossless.

## R08 corrections

R08 (`data/fm-ss-r08/report.md`, reviewed head `ea77944e`) did not accept the slice. Each finding's disposition:

- **F1 (blocking): A→B→A no longer reads as a stale ready.** Each event carries its source stream (pull request,
  remote worker, board message) as `causationId`. A source deduplicates only against its own latest observation,
  and each content change in a stream is a new transition with its own consequence key. Red→green→red is three
  owner-visible transitions, and readiness reports red with the earlier ready recorded as invalidated. A second
  source seeing the current state is still one consequence with both provenances.
- **F2 (blocking): a full pr-watch spool fails the run.** If waiting files plus this run's observations would exceed
  256, the script writes nothing, does not move `prs.json` and exits non-zero with the reason on stderr. The plugin
  reports the failure once, and the next run after ingestion retries the same changes.
- **F3 (blocking): long turns are paged, with gaps.** With an empty hook timeline, board correlation reads back up to
  eight 32-entry pages of the public typed refetch. It applies S02's qualification (same agent, same epoch, no
  `gap`/`staleCursor`/`reset`, no `error`) and stops once it has passed the oldest open message's time. Not finding
  a message within those pages, or any disqualified page, records a board source gap (`page-gap`, `malformed`,
  `epoch-changed`, `fetch-failed`, `empty-timeline`). A text-only match no longer blocks a later typed read: it may be
  upgraded once, inferred→verified.
- **F4: stale reservations reconcile.** `ScopedBoardSteer.reconcile()` turns a `reserved` submission older than five
  minutes into `uncertain`; it is never resent. A typed read settles a reserved or uncertain submission as accepted;
  text alone never does.
- **F5: unknown outcomes are visible.** The inbox status counts `unknownBoardSends` (reserved or uncertain) and adds
  a problem line per message. The field is optional in the RPC schema, so older clients are unaffected.
- **F6: separate observation budget.** S08 writes (observations, gaps, PR bindings, new board reservations) are
  refused with `HELD` once the pilot journal's sequence reaches **128**. The 128–192 band stays for gateway
  effects, and 192–256 for reconciliation, as before. Completing an existing board submission (settle, its
  correlation event) is exempt: at most two transactions per reservation. A separate store would avoid the shared
  ceiling altogether, but it would add a second coordinator and journal lifecycle. This explicit reserve is the
  smallest sound change; enabling any adapter on a long-lived journal still needs the planned measured storage
  work. Unchanged polls still write nothing.
- **F7 (install note).** The live home's `pr-watch` is an untouched seeded copy. **Installing this version rewrites
  it** to the S08 text, as every untouched built-in follows the plugin; schedule, enabled state and default output
  are unchanged. That is a watch *definition* change reaching the live home, so it needs watch-configuration
  authority at install time, not only at activation.
- **F8:** spool files are checked with `lstat` (regular files only, links not followed, size before read). A file is
  removed only when the journal holds its observation; a refused admission leaves it in place.
- **F9:** reviewer exclusion and the author check compare logins case-insensitively.
- **F10:** `observeRemote` observes only the current attempt of an active scoped owner. Finished attempts and
  legacy-mode scopes are not observed.
- **F11:** an item-thread retry of an already recorded message replays its record before the scoped check runs.
- **Readiness in this fleet.** The fleet's agents share one GitHub account, and GitHub forbids approving one's own
  pull request. So with `requiredApprovals ≥ 1`, `prReadiness` stays `blocked` until a human approves; independent
  reviewer runs cannot satisfy it through GitHub reviews. This is conservative, and activation must say so.
- **Remote guard fail-open.** Accepted for S08, because no scoped remote attempt can be created at this head. Before
  S11 (or anything else) creates scoped remote attempts, the guard must either fail closed for any worker it cannot
  positively classify as legacy, or rest on a journal-independent identity. The `index.server.ts` wrapper has no
  direct test.
