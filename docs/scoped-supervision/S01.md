# S01: scoped transaction journal and read projection

This slice is an unwired storage foundation. No RPC, request-file consumer, plugin lifecycle hook,
timer, supervisor, send, native resource creation or live migration calls it. Writes default off.
`SupervisionStore(..., { writable: true })` is used only by isolated fixtures in this delivery.
`read()`, `backend()` and `workflowRequest()` never initialize, claim, publish, repair or probe a
process. Every status says `executable: false` and `cooperative-storage-only`.

## Storage and publication

The caller supplies the plugin's data directory. The store uses
`<dataRoot>/supervision/<digest(homeId)>/` with an explicit identity, append-only coordinator
generations, numbered transactions and content-addressed evidence blobs. The library does not read
or migrate any existing home, workflow directory, config or live history by itself.

`transact(expectedVersions, requestId, mutations)` validates the complete next projection and
uniqueness indexes before writing. Each changed row needs one expected version; additional expected
rows can pin read dependencies. A transaction contains the exact canonical request/body digest,
captured actor provenance, generation, deterministic mutations, resulting versions/projection digest,
timestamp and an empty outbox. There is no delivery engine in S01. Row/identity tombstones have no
deletion API. Scope/task/backend/workflow/effect reservations commit in the same record.

Publication uses the existing fsync + exclusive-hard-link primitive in this order:

1. Sync and exclusively link the expected tip, retaining ownership/attempt/spend capsules.
2. Sync and exclusively link the whole transaction event.
3. Sync and exclusively link the independent publication marker with the same capsule.
4. Return the receipt. There is no external dispatch boundary in this slice.

The canonical encoder's existing callers retain their encoding and publication order. Optional
boundary hooks exist for crash qualification; there is no rename fallback. Blob bytes sync before
their transaction references. Unreferenced blobs/temps are inert; they are never authority.

Accepted request replay returns its original receipt before current CAS checks, even through a
read-only store. A different canonical body or provenance under the same ID conflicts. Workflow
request lookup retains original command/event hashes and the owning transaction receipt. Replay
does not execute an action or reconsider a historical approval.

Corrupt, missing or inconsistent authority holds the entire scoped store because one transaction
could own multiple scopes. Status retains the valid published prefix and independently checked
capsules as stale, non-executable evidence. Removing an exposed event and tip still leaves a
publication witness. Reads never repair. An explicit coordinator can finish the exact validated
final event+tip publication; it cannot reconstruct or drop a missing event/anchor. S01 deliberately
leaves missing-event anchors held: it has no launch inventory adapter with which to establish safe
removal. Thus there is no automatic anchor deletion or recovery-receipt/removal crash path to claim.

The default 100 MiB journal/blob alarm refuses new writes without evicting history; status reports
bytes and the configured bound. The unhandled-event alarm belongs to S02's queue, which does not
exist here. Opaque event payload quarantine also belongs to S02; S01's referenced blob hashes are
authority evidence and corruption holds their store.

## Coordinator boundary

Claiming a generation is explicit. Windows probes PID plus `Get-Process.StartTime` UTC ticks through
the system PowerShell executable; Linux reads boot ID plus `/proc/<pid>/stat` start ticks. Probe
failure/unsupported platforms return unknown. A live/unknown previous owner blocks acquisition.
There is no TTL takeover. Confirmed process death/PID reuse, or an explicit release serialized after
in-process writes, allows one exclusive next-generation claim. Stale instances cannot append.

Process death does not resolve a child or external operation. Dispatching/uncertain effect IDs,
attempt spend and resource IDs remain visible across generations. S01 performs no automatic effect
retry or actor replacement. Windows and Linux process-crash fixtures exercise the same implementation
in the repository's existing CI matrix; native receiver/external-boundary qualification is S04/S11.

These are cooperative same-user filesystem records. Captured actor kinds distinguish captain UI,
mate chat, agent and system provenance; none authenticates a caller. A peer with raw filesystem or
native/shell access can bypass this library. No receiver fencing, credential isolation, native
callback transfer, strong enforcement or automatic failover is claimed.

## Workflow reuse and backend partition

`WorkflowEventSchema` exports the existing schema unchanged. `replaySupervisionWorkflow` checks
original committed hashes **before** applying schema defaults, exactly as `WorkflowPlanStore.events`
does, then calls the existing `replayWorkflowEvent`. It is a historical replay seam, not admission for
new commands. S03 must perform revision/subject, current approval, dependencies, policy, brief,
budget and caller checks before supplying a newly admitted event. No second reducer/plan definition
model, workflow simplification, live import, release adapter or executor is added.

The projection retains removed-node ownership, prior attempts, cumulative budgets, historical early
answers, source provenance and retirement receipts. A closed trial satisfies done, never landed.
Retirement keeps its plan ID and scoped reservations; unrelated new plans cannot reuse them.

Backend reads choose one recorded backend, or return held/unknown. Prepared/held/retired backend
states and held/transferring/retired owners deny eligibility. Missing/corrupt authority never falls
back to legacy. Changing backend/source/owner or reactivating a barrier is refused: S07 owns the
checked source/delivery cutover protocol and S04/S07 must integrate both actual writer paths.
The journal barrier fixtures are **A13.store only**, not claims that L1–L5 or live legacy delivery
conversion exist. Existing legacy stores/readers remain untouched.

The SIGKILL tests qualify process/filesystem behavior, not disk or power-loss survival. Coordinated
loss of a journal and **all** local witnesses can hide truncation; no local algorithm here detects
that. An approved independent backup and external-effect reconciliation remain required before
migration/restore. No complete legacy migration, launch-inventory recovery, actual full-disk test,
model cost saving or live concurrency milestone is claimed by this slice.

Activation remains gated: independent R01 against the exact delivered head; resolution of blockers;
separate landing authority; S02/S03/S04 admission/effect integrations and their reviews; applicable
D1–D6 choices and exact installed-version/install/routing approval at their stages. There is no live
enable command in this delivery. Rollback means stop new admissions and retain held authority;
deleting the journal, resetting budgets, reusing retired IDs or restoring an incompatible writer is
not a supported rollback.
