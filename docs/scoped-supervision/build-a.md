# Build A acceptance contract

Project mates and durable project ownership are default-off. This build does not activate, provision or attach live scopes; rollout belongs to the captain after review. Plan execution, everyday scoped chat and maintenance are separate builds.

The following automatic checks define acceptance before implementation:

| Audit acceptance IDs | Required automatic evidence |
| --- | --- |
| A01, A13, A18 | One shared owned coordinator; concurrent/stale requests refuse; shutdown/restart retains identity and uncertainty. No second Attach path. |
| A12, A22 | History and accepted request replay survive journal paging beyond sequences 128/160/192/256, pressure and restart. Corruption/truncation holds remain; no history reset or budget refund. |
| A09, A15 | Every active registry entry is admitted or explicitly held, canonical project identities/aliases are stable, and project-plan membership distinguishes legacy pending migration from scoped sponsorship. Reads create no resources. |
| A01, A15, A20 | Duplicate project provisioning/intake produces one identity; independent workspace/session, durable profile/context/caps and cumulative spend survive restart. Plugin-owned admission reserves configured General headroom. |
| A05, A15 | A project stop holds only affected starts; an unrelated project continues. Cross-project plans retain one sponsor and one execution owner. |
| A11 | Memory proposal/CAS transport and confined capped digest-verified accepted text reader; memory/context never authorizes effects. |

Validation commands: `npm run typecheck`, `npm test`, focused Build A service/storage fixtures, `node docs/ship-deck-canvas/compile.mjs`, and affected UI render checks in both themes at desktop/phone browser widths. Fixtures use temporary homes/synthetic providers only. The completed PR will record exact commands/results and map new fixtures to this table.

## Delivered contracts

`FIRSTMATE_PROJECT_MATES=1`, sampled at startup, enables explicit administration and the project provision button. Absent or any other value leaves mutations off. Enabled views still initialize nothing. Provisioning is an unverified app convention, with no helper/CLI provision or Attach operation. S09 administration uses the existing current-mate role convention, preserving `mate-chat` provenance with an explicitly unverified source; it does not manufacture an authenticated captain. U1–U3, raw caller confinement and native subscription transfer remain unsupported.

`SupervisionRuntime` owns one store/coordinator per absolute home, shared by activation and project services. Acquisition and cleanup serialize; independent service callbacks do not hold its runtime lock during network IO. Shutdown drains callbacks before releasing ownership. Explicit mutation retries can complete an exact pending publication or rebuild a derived index after validating its ancestor checkpoint. Reads never repair. Missing, shortened or divergent history remains held.

The first explicit project mutation publishes an immutable, home-bound capacity receipt pinned to the existing sequence/hash. The original prefix is retained byte-for-byte. Subsequent transactions use 256-event directories with one uninterrupted global hash chain. Warm indexes keep request/receipt and original workflow-request metadata, not transaction bodies; their size counts toward pressure. Startup still audits all history. Bounded `historyPage` reads pin the inspected head and return at most 100 receipts. Defaults are 1 GiB physical history and 64 MiB projection/index, with no eviction or reset. Source, maintenance and paid admission bands stop progressively before a fixed 16 MiB reconciliation reserve plus 64 KiB per unresolved effect/cutover; projection pressure also reserves room for obligations. S07 keeps its bounded cutover inventory, body cap and abort reservation, using the same byte policy after upgrade. Turning the feature off does not remove this receipt or restore pilot ceilings. Older readers that cannot understand the receipt/pages must hold, never downconvert or erase them.

Registry identities derive from canonical local directory, normalized host and home. Each row is admitted or visibly held, including malformed/duplicate rows, unavailable directories and remote/URL entries requiring explicit mapping. Reviewed aliases survive project naming changes without inventing a new identity. Admission pins current reviewed S03 source bytes and explicit allocation, profile and cumulative session/turn caps. Provisioning rechecks project version, source bytes and registry identity inside each final gateway claim. Workspace/create/verify/opening retain S04 ordering and identity; unknown create/opening outcomes retain spend and never authorize a fresh identity or blind resend. Dormant native sessions persist without a timer or routine summary cascade.

S09 project/stop/allocation, sponsor/release/promotion, intake/conflict/dependency and memory commands are exposed by strict RPC and `tools/projects.mjs` through the existing workflow clock. The helper is seeded only while enabled. It exposes no provisioning or Attach. A legacy association is read-only pending migration. Sponsorship requires an authoritative scoped plan and complete legacy inventory/cutover; it never creates another plan writer or execution owner. Accepted/project-proposed memory uses capped, confined, digest-verified UTF-8 reads and stays context with authority `none`. General headroom applies to new plugin scope-session admissions (including the existing Attach path while this feature is enabled); raw/native callers and actual provider quota remain outside this cooperative policy. Ongoing worker dispatch, mailbox handling, everyday scoped chat and rollout metrics/trials belong to the subsequent builds.

Home and Plans show the same collapsed ownership census, expanding into project sessions, associations and retained spend, with existing native-session links and read-only memory review. An explicit confirmation names the durable profile and limits before provisioning. Lost responses keep the same request; stale or unreadable status disables confirmation. UI fixtures use the real component with synthetic host APIs, not an installed device or live rollout.
