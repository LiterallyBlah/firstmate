## Integration

`server/supervision-lifecycle.ts` composes the existing store, S02 ingress/mailbox, sessions and
gateway. All components must share the same store. Enablement is constructor-only for isolated
fixtures; there is no setting, environment switch or RPC activation. `index.server.ts` does not
import or attach this module. The explicit hook attachment uses the installed plugin types.

Each owner has an independent queue. Worker facts commit through S02 before an offer. Preparing
an offer does not spend a turn. Reserving its model turn commits the S02 send-uncertainty claim
and the counted S04 effect in one transaction. Gateway dispatch publishes its final authority
check/claim before calling the receiver, outside the publication lock. A slow native send in one
scope does not occupy another scope's admission queue or General's conversation lock.

A crash before dispatch resumes the same reserved effect. A dispatching/uncertain send is never
resent. A lost acceptance write is recovered from its succeeded effect; a fast owner acknowledgement
or retired old-epoch offer is not regressed by a late result. Acceptance handles neither the page
nor the goal. S02's explicit acknowledgement, per-event result and contiguous watermark remain
authoritative. Only a bound scope actor can use the mailbox commands through the helper.

S03 external command/answer outboxes are included directly in the owner's context. Authored
command identity is a semantic input; handling it is not. The helper exposes the existing S03
acknowledgement method: first commit the exact `ack handled` plan command, then reference that
command receipt for the matching outbox/decision/causation. It cannot substitute send acceptance.
Owner-authored routine command outboxes do not generate another owner wake.
Wake hints carry at most four outbox IDs and a total count; `scope.mjs read` pages the retained
inbox or pending outboxes without recording handling. The final rendered context is capped at
24 KiB. Overflow refuses the send while retaining the page and obligation.

`wake` handles event and owner-turn-end triggers. `recover` is the explicit restart/existing-heartbeat
seam: exact intent reconciliation, exact local worker observation through S02, then independent
scope wakes. It creates no heartbeat. Unknown lookups preserve attempts; neither idle nor a
reported status line records done. No native parent callback to General is created or retargeted.

Mailbox facts and external command identities extend the existing continuation input version.
Offer state, acknowledgements, journal sequence and the assessment's own writes are excluded.
One cause reserves one model pass. An incomplete/unchanged pass retains its due obligation without
an automatic retry loop. Explicit bounded capacity/prerequisite waits use the accepted continuation
contract. A definite capacity failure retains its counted turn and failure receipt; there is no
unapproved model fallback. A pause/hold wins admission and leaves the work visible.

`goalStatus` is the S05 projection seam: goal owner/epoch, next action or wait, verified active
worker count, reserved/live effects, uncertainty, evidence time/age and the last supervisor failure.
Project rows aggregate workers/effects, owners, per-goal next reasons and evidence age. A reserved
start with no verified worker counts as zero workers. Worker nesting/native parentage cannot move
its logical task ownership. Reads create no sessions, resources, decisions or assessments.

## Partition and authority

`workflowStore` gives the existing legacy workflow store a read-only supervision route guard at
its mutation boundary, covering helpers and existing UI callers. Uninitialized supervision creates
nothing. A scoped/retained plan or task-host identity refuses legacy mutation, including an implicit
one-run start under another plan name. Unrelated legacy plans remain usable. The scope helper
refuses live/quarantined legacy plan or task identities and an unavailable legacy inventory.
This is new-plan partitioning; it performs no cutover or historical migration.

Scoped starts always use `startWorker`; the older plain scoped workflow seam refuses start/claim/
implicit operations. S04 explicitly refuses remote worker/supervisor lifecycle mutation. Merge,
deploy, discard, publish, release and install have no gateway adapter. Archive proposals retain the
existing complete-persisted-inventory requirement, terminal-outcome requirement and final recheck.
Without U3 it remains check-then-archive with a native race, never conditional archive or takeover.

The request-file actor is cooperative same-user identity, not authentication. Epoch checks fence
this gateway only. Full-access shell/native calls remain outside its enforcement. No heartbeat gap,
lease expiry, negative listing or archive timeout proves quiescence. Replacement is manual after
the exact old actor is observed stopped; obligations, attempts, spend and uncertainty are retained.

The v1 receiver contract intentionally accepts only `synthetic-fixture` qualification. No live
adapter can be enabled by changing a flag. A later qualified adapter/format and durable policy
source need their own reviewed change and exact activation authority. This PR does not claim
operational concurrency, provider availability, latency improvement, native fencing or live acceptance.

Freeze admissions for rollback. Retain the journal, inbox, receipts and reserved resources;
reconcile uncertain effects before any manual higher-epoch replacement. Do not restore stale
authority or refund spend. Historical C2/normal experiments and their holds remain untouched.
No new compile/empty-job/native ownership probe was used to replace their missing disposition.
